## 背景

请假 / 报修 / 路线模板三组页面按 claude.ai 语言重做后，在 HTML 原型（缩小、假数据）上通过，但在 Pixel 4（393×829dp、1:1、真实数据）上走查暴露两类问题：

- 视觉：页头固定占掉约 1/4 屏；右侧状态列挤掉标题；值全加粗等于没有重点；固定三列选项把“IT（智能电子设备）”折行；空态正文左对齐出现“你。”单独成行；危险动作贴着返回键。
- 逻辑：报修详情用过期 `dqzt` 导致已完工的单显示“待处理”且可撤回；维修员电话回退成报修人号码；报修“进行中”把取消 / 废单算进去；请假计数随 tab 在 1 与 10 之间跳；跨年记录排序错乱；请假待销假状态被当成待审批、超假信息沉到页底；“销假”动作实际不可用；开发者文案外露。

结论：这类问题必须在真机 + 真数据上验收，HTML 原型只用于探索视觉方向，不能作为验收依据。

## 决定

1. **页头跟着滚**：列表 / 详情 / 新建的 `LxPageHeader` 都放进滚动容器首个 item；`LxNavBar` 在滚动超过 ~36dp 后淡入小标题并显示底部分隔线。
2. **状态进信息行**：列表行不再保留右侧状态列；状态点 + 状态文案 + “类型 · 地点 · 日期”合成标题下的一行（`LxStatusLine`）。待处理 / 待销假 / 已派单等着色，已完结只保留圆点、文字退回灰色。
3. **分段 tab**：`LxFilterTabs` 是一条底轨上的分段控件（选中白块），不再“选中像按钮、未选中像文字”。
4. **默认 tab 看数据**：报修“进行中”为空时落到“全部”，不再先给空页；请假首屏加载 `status=1`，为空时自动切到 `status=3`，用户手动选过则不再自动改。
5. **值用常规字重**：`LxMetaGrid` 的值 14.5sp 常规字重；编号、地址、学院等长值独占一行（`lxMetaIsWide`）。重点交给状态块和标题，不再“八个粗值”。
6. **选项按文字宽度换行**：`LxChoiceGroup` 在 ≤3 个短选项时等宽平铺（两个选项即分段控件），否则 `FlowRow` 按内容宽度换行，不再固定三列。
7. **空态正文居中**：`LxEmptyState` 标题与正文都居中；正文文案避免以单个“你。”收尾。
8. **动作位置**：
   - 详情页危险动作（撤回）从右上角移到内容底部，点击后再确认；表单提交固定在底部 `LxBottomBar`。
   - 列表页主动作（发起请假 / 新建报修 / 导入模板）改为右下 `LxFloatingAction`，不再放右上角小字。
   - 模板详情：导出 / 重命名是两个 `LxGhostButton` 并排；删除模板是页面最底部独立的 `LxDangerButton`。
9. **报修状态以服务端完成为准**：`getBxdXqForSjd.do` 的 `dqzt` 会过期（HAR 实证：已完工单详情仍返回 `dqzt=9 待处理`），入库前按 `wcqk=1 / fwpj=1` 修正为 `dqzt=4 维修完成`；进入详情时再用列表摘要补 `dqzt`、`wxySjh`。
10. **撤回只在未完成时出现**：`dqzt ∈ {1,9}` 且 `completed=false`；列表“进行中”用白名单 `{1,2,3,9,11}`，取消 / 废单 / 延单 / 完工不计入。
11. **请假计数用服务端 `total`**：`myExecution.do` 的 `{rows,total}` 是唯一计数来源；“进行中”扣掉服务端仍归在 `status=1` 里的“已撤回”，拿不全时宁可不显示数字。列表按 `receiveTime` 倒序，并按“2026 年 6 月”分组、行首显示“01 周一”。
12. **销假走待办节点**：销假不是回写 `getXjxx.do` 的展示信息，而是从 `getRunTaskByUserCode.do {approvedType:3}` 取该申请的 `ruTaskNodeId`，再 `POST agree.do { dataJson, executionId, ruTaskNodeId, stuQjsq:{xjfjList:[]} }`。超假信息前置到状态块下方并带单位。
13. **文案不露实现**：删除“字段由学校服务端下发”“销假信息不是可回写的表单结构，仅展示。”“评价已在服务端提交，此处只读展示。”等开发者说明。

## 理由

- 真机 1:1 才是真实版面：页头固定 + 右侧状态列在 393dp 上直接挤压标题与地址，这是 HTML 缩小原型看不出来的。
- 状态放进信息行后标题可以占满整行；状态着色只用于“需要你处理”的项，完结项用灰字压下去。
- 计数必须来自服务端；客户端数已加载页会在切 tab / 翻页时变化，且“进行中”的黑名单会漏掉或误收状态。
- 撤回是破坏性动作，贴着返回键必然误触；放到内容底部并二次确认。
- 销假的真实协议只在 H5 `XjDialog` 里（`agree.do` + `ruTaskNodeId`），此前“只在 xjxx 含 QJRQ/dataJson/flowTitle 时显示按钮”的条件永远不成立，动作等于不存在。

## 考虑过的替代方案

- **保留右上角“发起 / 新建”**：会被用户点名“大屏够不到、不显眼”，改为 FAB。
- **值继续全部加粗**：详情一屏 8 个粗值没有层级，改为常规字重 + 状态 / 标题承担重点。
- **请假计数用已加载列表 + 黑名单**：切 tab 即在 1 与 10 之间跳，不采用。
- **销假继续只读展示**：动作等于没有，且用户要求“销假走通”，改为按 H5 协议提交。
- **继续用 HTML v4 原型验收**：原型缩小 + 假数据会再次掩盖真机问题，本轮不再画原型，直接 Compose + Pixel 4 截图验收。

## 后果

- 页面首屏内容上移，列表页在滚动后才出现导航小标题；截图验收需同时看“顶部”和“滚动后”两态。
- 请假“进行中”不再显示“已撤回”（它们只在“全部”里出现），与 H5 的服务端口径有意不同。
- 报修详情状态可能与详情接口原始 `dqzt` 不一致，这是修正而非 bug；排查时先看 `wcqk/fwpj`。
- 销假提交依赖 `agree.do` 与 `ruTaskNodeId`；拿不到待办节点时按钮不出现，给出“返回列表刷新后再进”的提示。
- 旧决策「值 600」「导航栏无标题」「模板动作用文字链」「报修默认停在进行中（0 条也保留）」被本篇取代，详见 `2026-10-18-decision-claude-ui-language.md` 的“后续修订”。

## 验证

- `assembleDebug` 成功；`testDebugUnitTest` 129 通过、0 失败（新增 `RepairStatusTest`、`LeaveListLogicTest`）；`lintDebug` 0 error / 102 warning / 4 hint。
- Pixel 4 / Android 13 真机走查（安装 debug APK，逐页截图）：
  - 请假列表：进行中 1 / 全部 14，按年月分组，跨年记录倒序正确，已撤回只出现在“全部”。
  - 请假详情（待销假）：超假 139 天前置，销假按钮可用（`ruTaskNodeId` 来自待办）；已完结记录显示“已完结”、三步全灰、纯日期区间正确显示星期与天数。
  - 发起请假：类型 → 起止时间 → 是否离校 → 事由 → 联系人 / 地址 → 附件；审批规则收成一行；提交固定在底部；起止时间同一弹层，默认下一个整点、5 分钟步进。
  - 报修列表：进行中 0 / 全部 12，状态与信息合成一行；已完工单详情显示“维修完成”，无撤回，维修员电话取列表 `wxySjh`。
  - 模板列表 / 详情：导入模板为 FAB；导出 / 重命名为并排按钮，删除模板单独在底部。
- 销假提交未在真机上实际点击（会向学校提交真实销假申请），协议按 H5 源码逐字段核对；留给用户一键验收。
